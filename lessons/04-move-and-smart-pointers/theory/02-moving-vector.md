# Конструктор и оператор перемещения

Теперь оформим знакомую передачу массива в специальные функции `Vector`. Сохраняем договорённость: после передачи другому объекту источник пуст — `arr_ == nullptr`, `size_ == 0`. Полная реализация находится в [практике](../practice/vector.cpp).

## Новый объект: конструктор перемещения

```cpp
Vector source(2);
source[0] = 10;
Vector result = std::move(source);
```

Последняя строка создаёт `result`, поэтому здесь нужен **конструктор перемещения**. В публичной части класса объявим `Vector(Vector&& vec) noexcept;`, а реализацию запишем так:

```cpp
Vector::Vector(Vector&& vec) noexcept
    : arr_(vec.arr_), size_(vec.size_) {
    vec.arr_ = nullptr;
    vec.size_ = 0;
}
```

Параметр `Vector&&` принимает источник, который разрешено изменить. Список инициализации записывает адрес массива и размер в новый объект. Тело делает источник пустым. Новый массив не выделяется, элементы не копируются.

Обнулить только размер недостаточно: деструктор выполняет `delete[] arr_`, поэтому оставленный адрес привёл бы к повторному удалению. После примера `result` содержит прежние данные, а `source.size()` равен нулю.

## Существующий объект: перемещающее присваивание

Теперь получатель уже владеет своим массивом:

```cpp
Vector active(1000);
Vector prepared(2);
active = std::move(prepared);
```

Конструктор повторно не вызывается. Нужно удалить прежний массив `active` и принять массив `prepared`. Это задача **оператора перемещающего присваивания**, который также называют оператором перемещения:

```cpp
Vector& Vector::operator=(Vector&& vec) noexcept {
    if (this == &vec) {
        return *this;
    }

    delete[] arr_;
    arr_ = vec.arr_;
    size_ = vec.size_;
    vec.arr_ = nullptr;
    vec.size_ = 0;
    return *this;
}
```

Объявление в классе — `Vector& operator=(Vector&& vec) noexcept;`. Слева от `=` находится получатель, параметр `vec` обозначает источник. Возвращаемая ссылка `*this` — сам получатель после присваивания.

От конструктора реализация отличается освобождением **старого ресурса получателя**. Проверка адресов защищает от `v = std::move(v)`: в нашем классе такое присваивание оставляет объект без изменений. Без проверки алгоритм сначала удалил бы собственный массив.

Пустые векторы не требуют отдельной ветки. Если получатель пуст, `delete[] nullptr` безопасен. Если пуст источник, получатель освобождает прежний массив и тоже становится пустым.

## Состояние источника и noexcept

Перемещение не заканчивает жизнь источника. Его деструктор всё равно будет вызван, поэтому источник должен оставаться корректным. Наш пустой `Vector` можно уничтожить или заполнить заново:

```cpp
Vector source(2);
Vector result = std::move(source);
// source[0] = 7; // Нельзя: элементов сейчас нет.
source = Vector(1);
source[0] = 7;    // Теперь элемент существует.
```

Пустота после перемещения — договорённость **нашего класса**. Например, для перемещённой `std::string` в общем случае гарантируется корректное, но не обязательно пустое состояние. Её можно уничтожить, присвоить новое значение; перед чтением первого символа нужно проверить, что строка непустая.

В наших move-операциях нет выделения памяти: только работа с адресами, числами и удаление массива `int`. Эти действия не выбрасывают исключений, поэтому подходит знакомое [обещание `noexcept`](../../03-exceptions/theory/02-unwinding-and-ownership.md).

Это полезно и вызывающему коду. Например, стандартный `std::vector<Vector>` при росте может переносить свои элементы — наши векторы — в новый буфер. Если перемещение способно бросить исключение, уже изменённые источники трудно восстановить. При доступном копировании контейнер может выбрать его ради сильной гарантии. Конструктор перемещения с `noexcept` позволяет безопасно использовать передачу ресурсов. Ставить `noexcept` без проверки реализации нельзя: он не устраняет возможные ошибки.

## Пять связанных функций

У владельца сырого массива согласованы пять операций:

```cpp
~Vector();
Vector(const Vector& vec);
Vector& operator=(const Vector& vec);
Vector(Vector&& vec) noexcept;
Vector& operator=(Vector&& vec) noexcept;
```

**Правило пяти** рекомендует рассматривать их вместе, если класс сам управляет ресурсом: копирование создаёт независимый массив, перемещение передаёт его, деструктор освобождает то, чем объект ещё владеет. Это не требование писать пять функций в каждом классе.

У версии из занятия 2 были пользовательские деструктор и копирующие операции, поэтому move-операции не появились автоматически. Запись `= default` просит компилятор выполнить соответствующую операцию над каждым полем, но нашему классу такое перемещение не подходит: поле `int*` просто скопирует адрес, не обнуляя источник. Снова получатся два владельца одного массива.

В следующей части готовые владельцы позволят некоторым классам вообще не писать эти функции вручную.

## Возврат по значению

Возврат результата не всегда требует даже перемещения:

```cpp
Vector makeMeasurements() {
    Vector result(2);
    result[0] = 10;
    return result;
}

Vector a = makeMeasurements();
a = makeMeasurements();
```

При инициализации `a` компилятор может создать локальный `result` сразу на месте `a`. Это **NRVO** — оптимизация возврата именованного объекта. Тогда между ними нет ни копирования, ни перемещения. Если NRVO не выполнена, наш класс использует конструктор перемещения.

Во второй строке вызова `a` уже существует: результат функции передаётся ему оператором перемещающего присваивания. Если же функция сразу пишет `return Vector(2);`, в C++20 результат создаётся непосредственно в месте назначения без промежуточного копирования или перемещения.

Пишите `return result;`, а не `return std::move(result);`: во втором варианте теряется возможность NRVO. Для показанной локальной переменной язык уже предусматривает перемещение, если оно понадобится.

**Проверьте себя:** какие операции выполняются здесь?

```cpp
Vector a(2);
Vector b = a;            // 1
Vector c = std::move(a); // 2
b = std::move(c);        // 3
const Vector saved(2);
Vector d = std::move(saved); // 4
```

<details>
<summary>Ответ</summary>

1. Конструктор копирования: отдельный массив.
2. Конструктор перемещения: массив передан, `a` пуст.
3. Перемещающее присваивание: прежний массив `b` удалён, `c` пуст.
4. Конструктор копирования: `std::move` не снимает `const`, поэтому параметр `Vector&&` не подходит.

</details>
