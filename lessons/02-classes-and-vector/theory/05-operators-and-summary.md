# Перегрузка операторов: что означает a + b для Vector

Наш `Vector` уже можно создать, скопировать и изменить. Теперь хотим использовать его в вычислениях так же понятно, как обычные числа.

Для двух `int` выражение `a + b` имеет смысл, заданный языком. Но компилятор не знает, что должно означать сложение двух объектов нашего класса. Нужно ли складывать соответствующие элементы? Или соединять два массива в один? Само наличие поля `arr_` не даёт ответа.

Автор класса выбирает смысл операции и пишет её реализацию. **Перегрузка оператора позволяет вызвать эту реализацию привычной записью `a + b`.** Основная задача этой части — увидеть связь между знаком оператора и функцией, которая выполняется за ним.

## Сначала договоримся о поведении

Для нашего `Vector` выберем поэлементное сложение:

```text
[10, 20] + [1, 2] → [11, 22]
```

Размеры должны совпадать. Исходные векторы сохраняют значения, а результат получает собственный массив. Если размеры различаются, операция сообщает об ошибке.

Это договор нашего класса. Перегрузка оператора сама по себе не гарантирует ни сложения элементов, ни сохранности исходных данных — всё это обеспечивает написанный нами код.

## От обычного метода к оператору

Такую операцию можно было бы оформить методом с именем `add` и вызывать как `a.add(b)`. Для записи `a + b` в C++ используют специальное имя метода — `operator+`.

Внутри класса объявляем:

```cpp
Vector operator+(const Vector& other) const;
```

В нашем проекте эти две записи вызывают один и тот же метод:

```cpp
Vector sum = a + b;
Vector sameSum = a.operator+(b);
```

Левый операнд `a` — объект, у которого вызывается метод; внутри он доступен через `this`. Правый операнд `b` передаётся в параметр `other`. Поэтому у метода один явный параметр, хотя в выражении участвуют два вектора.

В объявлении уже знакомые нам конструкции работают вместе:

- `const Vector& other` позволяет читать правый вектор без создания копии;
- `const` после скобок позволяет вызвать метод у константного левого вектора и выражает обещание не менять его;
- возвращаемый тип `Vector` означает, что результатом будет самостоятельный объект.

Мы уже использовали тот же механизм для `[]` и `=`. Для изменяемого объекта `a` записи `a[i]` и `a.operator[](i)` вызывают метод индексирования, а `a = b` и `a.operator=(b)` — оператор присваивания. Специальное имя функции связывает реализацию с соответствующей записью выражения.

## Реализация выбранного поведения

В `vector.cpp` определяем метод:

```cpp
Vector Vector::operator+(const Vector& other) const {
    if (size_ != other.size_) {
        throw std::length_error("Vectors must be same size");
    }

    Vector result(size_);
    for (int i = 0; i < size_; ++i) {
        result[i] = arr_[i] + other[i];
    }
    return result;
}
```

Сначала проверяем размеры, чтобы не читать элементы за границами правого массива. Затем создаём отдельный вектор и записываем в него суммы. `arr_[i]` — элемент левого вектора, `other[i]` — правого. Запись идёт только в `result`, поэтому исходные массивы сохраняются.

Само сложение `arr_[i] + other[i]` здесь выполняется для двух `int`. Мы используем обычное сложение чисел внутри собственной операции над векторами. Как и для любого `int`, сумма должна помещаться в его диапазон; проверку переполнения наш класс не добавляет.

Возвращать локальный `result` по ссылке нельзя: при выходе из функции его жизнь завершится, а возвращённая ссылка станет висячей. Возвращаем результат по значению. Компилятор может создать его сразу в месте назначения без отдельной копии локального `result`; точное число копирований сейчас не рассматриваем.

Для вызывающего кода остаётся различие из предыдущей части:

```cpp
Vector sum = a + b; // Новый sum инициализируется результатом сложения.
sum = a + b;        // Результат присваивается существующему sum.
```

Сложение в обеих строках выполняет `operator+`. Только во второй строке результат затем передаётся в оператор копирующего присваивания нашего `Vector`.

## Какие ожидания должна сохранять перегрузка

Запись `a + b` привычно читается как получение суммы с сохранением слагаемых. Поэтому наш `operator+` создаёт отдельный результат. Если бы он неожиданно изменял `a`, вызывающий код было бы трудно понимать, хотя сам язык не запрещает автору написать такой оператор.

Перегрузка меняет поведение операции для нашего типа, но не её приоритет или число операндов. Она также не создаёт другие операции автоматически: определение `operator+` не добавляет классу `operator+=`.

<details>
<summary>Другой способ реализации: свободная функция</summary>

Оператор `+` можно определить и вне класса:

```cpp
// Альтернатива методу класса, а не дополнительная перегрузка в нашем проекте.
Vector operator+(const Vector& left, const Vector& right);
```

Тогда оба операнда передаются явно, а `this` отсутствует. Свободная функция может работать через публичные `size()` и `operator[]`. В проекте оставлен метод класса; добавлять одновременно оба варианта с одинаковой ролью не нужно, иначе вызов `a + b` может стать неоднозначным.

</details>

## Проверим, что договор выполняется

```cpp
Vector a(2);
a[0] = 10;
a[1] = 20;
Vector b(2);
b[0] = 1;
b[1] = 2;

Vector sum = a + b;
std::cout << sum[0] << ' ' << sum[1] << '\n'; // 11 22
sum[0] = 99;
std::cout << a[0] << ' ' << b[0] << '\n';     // 10 1
```

Первый вывод показывает поэлементное сложение. Второй подтверждает, что изменение результата не затрагивает исходные данные.

При несовпадении размеров выполняется ветка с `throw`. В демонстрации вызывающий код обрабатывает её так:

```cpp
try {
    Vector a(2);
    Vector b(3);
    Vector sum = a + b;
    std::cout << sum.size() << '\n'; // При этой ошибке не выполнится.
} catch (const std::length_error& error) {
    std::cout << error.what() << '\n';
}
```

Для `std::length_error` нужен заголовок `<stdexcept>`. После ошибки управление переходит в подходящий `catch`, а `what()` возвращает сообщение. Перед переходом локальные `a` и `b` уничтожаются; `sum` не был успешно создан. Здесь обработка ошибки нужна, чтобы показать поведение операции для неподходящих размеров. Подробный разбор исключений будет отдельно.

**Перед продолжением:** какая функция вызывается для `a + b`, где она получает левый и правый векторы и почему возвращает `Vector`, а не `Vector&`?

Ответ: в нашей реализации вызывается `a.operator+(b)`. Левый вектор доступен через `this`, правый — через `other`. Возвращаем самостоятельный результат по значению, чтобы не отдавать ссылку на локальный объект.
