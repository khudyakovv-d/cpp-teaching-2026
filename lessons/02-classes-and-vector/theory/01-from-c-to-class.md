# От структуры к классу

На первом занятии мы разбирали, как собрать программу из нескольких файлов. Теперь посмотрим на другую задачу: как организовать сам код, когда программа становится больше и с одними и теми же данными работают разные её части.

В C мы уже умеем выделять функции и объединять связанные данные в структуры. Например, у прямоугольника есть ширина и высота, у даты — день, месяц и год, у динамического массива — указатель на элементы и размер. Структура позволяет передавать эти данные вместе и дать им общее имя.

Но смысл такого типа определяется ещё и правилами работы с ним. Для даты нужно учитывать число дней в месяце. Для динамического массива — следить, чтобы размер соответствовал выделенной памяти. Операции над данными должны соблюдать эти правила. На примере собственного `Vector` разберём, как выразить эту связь в программе.

## Какие правила связывают данные и операции

Нам нужен массив целых чисел, размер которого становится известен во время выполнения. В C его можно представить так:

```c
struct Vector {
    int* arr;
    int size;
};
```

Эти поля связаны по смыслу. Указатель сообщает, где находятся элементы, а размер — к скольким элементам можно обращаться. Если выделить память для трёх чисел, но записать в `size` значение 100, структура перестанет правильно описывать массив.

При этом компилятор C разрешает такую запись: 100 подходит для поля типа `int`. Связь между значением `size` и количеством выделенной памяти в объявлении структуры не выражена.

Чтобы работать с вектором, нужны операции: создать массив, узнать размер, прочитать или изменить элемент, скопировать содержимое и освободить память. В C обычно оформляют набор функций для одного типа:

```c
/* Объявления функций; реализацию здесь не приводим. */
int vector_init(struct Vector* v, int size);
void vector_destroy(struct Vector* v);
int vector_size(const struct Vector* v);
```

Уже по именам видно, что эти функции образуют общую группу со структурой `Vector`. Их нельзя реализовать независимо от её устройства. Например, функция создания должна согласованно установить указатель и размер, а функция уничтожения — освободить именно тот массив, которым владеет вектор.

## Кто отвечает за корректность вектора

Допустим, функции написаны правильно. Пока поля структуры открыты, вызывающий код всё равно может обойти их:

```c
/* Здесь v уже успешно инициализирован как вектор из трёх элементов. */
v.size = 100;
```

Памяти больше не стало. Если другая часть программы доверится новому размеру и начнёт читать сто элементов, она выйдет за границы массива. Ошибка внесена в одном месте, а проявиться может значительно позже.

Можно договориться, что никто не меняет поля напрямую. Но тогда каждый автор вызывающего кода должен знать внутренние правила вектора и соблюдать их. Чем больше таких мест, тем сложнее проверить программу. Изменение устройства вектора тоже потребует найти код, который опирается на его поля.

Хотим устроить работу иначе: автор типа отвечает за представление данных и операции, которые сохраняют его корректность. Остальной код использует эти операции. Например, он просит вектор сообщить размер или скопировать содержимое, а подробности хранения остаются внутри реализации типа.

Поэтому данные и основные операции полезно проектировать вместе. Для `Vector` выделение памяти, копирование и освобождение — части одного договора: кто владеет массивом, когда можно обращаться к элементам и кто их уничтожает. Если эти решения принимать отдельно, легко получить несовместимые правила.

Такой подход возможен и в C: функции можно объединить в модуль, а определение структуры скрыть от вызывающего кода. В C++ для выражения этой связи есть средства самого языка: методы, управление доступом, конструкторы и деструкторы. Начнём с методов и доступа к полям; создание и уничтожение разберём следом.

## Данные и операции одного объекта

Начнём с фрагмента класса. Пока он показывает только устройство типа, а не готовую реализацию:

```cpp
class Vector {
private:
    int* arr_;
    int size_;

public:
    int size() const;
};
```

`Vector` — имя типа. Переменная такого типа называется **объектом**. `arr_` и `size_` — **поля**, то есть данные внутри объекта. У каждого объекта свои поля: размер одного вектора не меняет размер другого.

`size()` — **метод**, функция, которую вызывают у объекта. Слово `const` после скобок обозначает, что метод доступен для чтения состояния без изменения самого объекта; подробнее разберём это в третьей части.

```cpp
// Фрагмент использования готового класса из проекта.
Vector a(3);
Vector b(5);
std::cout << a.size() << ' ' << b.size() << '\n'; // 3 5
```

Запись `Vector a(3)` создаёт объект размером 3. Как именно выделяется память, увидим в следующей части. Для вывода нужен заголовок `<iostream>`; `std::cout` уже встречался на первом занятии. Оператор `<<` последовательно отправляет значения в поток, а `'\n'` завершает строку.

В сравнении с C меняется форма обращения: вместо `vector_size(&a)` пишем `a.size()`. Объект, с которым работает метод, передаётся неявно. Но сама запись через точку ещё не защищает данные: для этого нужно определить, какие действия разрешены снаружи класса.

## Что разрешено пользователю класса

После `public:` располагаются операции, доступные снаружи. После `private:` — детали, доступ к которым имеют методы класса, но не обычный вызывающий код.

```cpp
Vector v(3);
std::cout << v.size() << '\n';
// v.size_ = 100; // Ошибка компиляции: поле private.
```

Для нашего класса договоримся о правилах:

- размер неотрицательный;
- у пустого вектора размер 0 и указатель `nullptr`;
- у непустого вектора есть собственный массив из `size_` элементов;
- два самостоятельных вектора не владеют одним массивом.

Такие правила называют **инвариантами**: они должны выполняться после успешного создания объекта и после завершения его публичных операций. Скрытые поля помогают их поддерживать, но не исправляют ошибки внутри самих методов.

Пользователь знает, что `size()` возвращает число элементов, и не обязан знать, где хранится массив. Это **абстракция** — описание доступных действий без деталей реализации. Объединение данных с операциями и ограничение доступа к внутреннему состоянию называют **инкапсуляцией**.

Не каждую функцию, которая принимает `Vector`, нужно делать методом. Например, функция вывода может читать элементы через публичный интерфейс и оставаться снаружи класса. С типом прежде всего связываем операции, которым нужно управлять его внутренним состоянием. Остальные функции могут использовать готовый тип, не зная его устройства.

В C++ и `struct`, и `class` могут содержать методы, конструкторы и закрытые поля. Для рассматриваемых объявлений разница только в доступе по умолчанию: у `struct` он `public`, у `class` — `private`. Структуры в C таких возможностей не имеют.

## Как метод связан с объектом

Объявление класса помещаем в `vector.h`, а определение метода — в `vector.cpp`, как разделяли объявления и определения на первом занятии:

```cpp
#include "vector.h"

int Vector::size() const {
    return this->size_;
}
```

`Vector::` сообщает, что определяется метод класса `Vector`. Внутри нестатического метода `this` — указатель на объект, у которого метод вызвали. Для `a.size()` он указывает на `a`, для `b.size()` — на `b`.

`this->size_` обращается к полю через указатель. В этом методе можно написать просто `size_`: компилятор понимает, что речь о поле текущего объекта. В коде проекта используем короткую форму, а явный `this` оставим там, где нужен адрес объекта.

**Перед продолжением:** почему `v.size_ = 100` не компилируется, а ошибка внутри метода всё ещё может нарушить связь указателя и размера?

Ответ: `private` ограничивает доступ извне; за корректность реализации методов отвечает автор класса.
