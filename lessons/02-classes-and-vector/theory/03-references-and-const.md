# Ссылки и `const`

У вектора уже есть размер и память. Теперь дадим пользователю возможность читать и изменять элементы. Сначала разберём два способа обратиться к существующему объекту — через указатель и через ссылку. Затем посмотрим, что именно можно запретить изменять с помощью `const`.

## Указатель хранит адрес

```cpp
int x = 10;
int y = 20;
int* p = &x;

*p = 42;
std::cout << x << '\n'; // 42

p = &y;
*p = 7;
std::cout << y << '\n'; // 7; x по-прежнему равен 42.
```

`p` — отдельная переменная типа `int*`. Её значение — адрес числа. `&x` получает адрес `x`, а `*p` обращается к числу по адресу, который сейчас хранится в `p`. Такое обращение называют **разыменованием**.

Здесь есть два разных действия. Запись `p = &y` меняет сам указатель: теперь он хранит другой адрес. Запись `*p = 7` меняет число по этому адресу. Без `*` работаем с указателем, с `*` — с объектом, на который он указывает.

```text
int* p = &x;          p = &y;

p ───► x: 42         x: 42
                     p ───► y: 20
```

Указатель может не указывать на объект: для этого используют `nullptr`. Например, `int* p = nullptr;`. Такой указатель можно хранить и сравнивать, но разыменовывать нельзя. Если отсутствие объекта допустимо, перед обращением проверяют `p != nullptr`.

## Ссылка обозначает тот же объект

```cpp
int x = 10;
int y = 20;
int& r = x;

r = 42;
std::cout << x << '\n'; // 42

r = y;
std::cout << x << '\n'; // 20
```

`r` — **ссылка** на `x`, другое имя того же объекта. Она не создаёт копию числа. Для работы через ссылку не нужно разыменование: выражение `r` уже обозначает `x`.

Ссылку связывают с объектом при инициализации. В объявлении обычной локальной ссылки нельзя оставить только `int& r;` без объекта. После привязки ссылка не может начать обозначать другой объект.

Поэтому `r = y` не перепривязывает ссылку. Это присваивание числа: значение `y` записывается в `x`. После него `r` всё ещё обозначает `x`. Запись `&r` тоже даёт адрес `x`, а не адрес отдельного объекта-ссылки.

Сравните действия:

- `p = &y` — перенаправить указатель на `y`;
- `*p = y` — записать значение `y` в объект по указателю;
- `r = y` — записать значение `y` в объект, с которым уже связана ссылка.

Знак `&` нужно читать в контексте. В объявлении `int& r` он обозначает ссылочный тип, а в выражении `&x` — получение адреса. Запись `*r = 42` для нашей ссылки неверна: `r` обозначает число, а разыменовывают указатель.

У корректной ссылки нет состояния «ни с чем не связана», аналогичного `nullptr`. Но это не гарантирует, что объект будет жить достаточно долго. Если он уничтожен, оставшаяся ссылка становится **висячей**. Указатель на уничтоженный объект тоже становится висячим. Использовать их для доступа к прежнему объекту нельзя; проверка указателя на `nullptr` эту проблему не обнаруживает.

Ни ссылка, ни обычный указатель сами по себе не продлевают жизнь объектов в этих примерах и не освобождают их память. Оба могут обозначать локальные или динамически выделенные объекты — размещение памяти разобрали в предыдущей части.

## Что именно запрещает изменять const

Начнём с самого числа:

```cpp
const int x = 10;
// x = 20; // Ошибка компиляции: x объявлен константным.
```

У указателя есть два уровня: сам указатель с адресом и объект по этому адресу. `const` позволяет ограничить изменение каждого уровня отдельно.

**Указатель на константное значение — `const int*`.** Через него нельзя менять число, но можно записать в указатель другой адрес:

```cpp
int x = 10;
int y = 20;
const int* p = &x;

// *p = 30; // Ошибка: через p число доступно только для чтения.
p = &y;     // Можно: меняем сам указатель.
std::cout << *p << '\n'; // 20
```

Записи `const int*` и `int const*` означают одно и то же. В обеих `const` относится к `int`, а не к самому указателю.

**Константный указатель — `int* const`.** Нельзя заменить адрес, который в нём хранится, но число по этому адресу менять можно:

```cpp
int x = 10;
int y = 20;
int* const p = &x;

*p = 30;   // Можно: меняем x.
// p = &y; // Ошибка: нельзя изменить сам указатель.
std::cout << x << '\n'; // 30
```

**Оба ограничения — `const int* const`.** Нельзя ни перенаправить указатель, ни изменить число через него:

```cpp
int x = 10;
int y = 20;
const int* const p = &x;

// p = &y;  // Ошибка: указатель константный.
// *p = 30; // Ошибка: число через p доступно только для чтения.
std::cout << *p << '\n'; // 10
```

В этих простых объявлениях удобно смотреть на `*`: `const` слева от неё относится к типу числа, справа — к самому указателю. Для обычного `int*` оба действия разрешены: можно менять и адрес, и число через указатель.

## Что означает const у ссылки

У ссылки нет отдельного изменяемого адреса. Она уже не может быть перепривязана, поэтому дополнительный `const` для запрета перепривязки не нужен.

Запись `const int&` означает **ссылку на число, доступное через неё только для чтения**. `int const&` — та же запись с другим порядком слов:

```cpp
int x = 10;
const int& r = x;

// r = 20; // Ошибка: нельзя менять x через r.
x = 30;    // Можно: сам x не объявлен const.
std::cout << r << '\n'; // 30
```

У `int&` и `const int&` одна и та же постоянная привязка к объекту. Отличается возможность записи в этот объект через ссылку. Объявление `int& const r = x;` недопустимо: так задать константность самой ссылки нельзя.

Это помогает точнее читать и указатели: `const int* p = &x` тоже не превращает исходный `x` в константный объект. Оно запрещает изменение **через `p`**. Если `x` изначально объявлен как обычный `int`, его можно менять по имени или через другой разрешающий запись доступ; ссылка или указатель для чтения увидят новое значение.

Если же сам объект объявлен `const int x = 10`, обычные `int&` и `int*` к нему привязать нельзя: это позволило бы обойти запрет на изменение. Для обращения к нему подходят `const int&` и `const int*`.

**Проверьте себя:** можно ли выполнить `*p = 5` и `p = &y`, если `p` объявлен как `int* const`? А если как `const int*`?

Для `int* const` разрешена запись в число, но не смена адреса. Для `const int*` — наоборот. Для `const int& r` запись через `r` запрещена, а перепривязки у ссылки вообще нет.

## Почему присваивание в элемент работает

Хотим писать `v[0] = 42`. Внутри класса объявим:

```cpp
int& operator[](int i);
```

Это **перегрузка оператора**: задаём, что означает `[]` для нашего типа. Выражение `v[0]` вызывает `v.operator[](0)`.

```cpp
int& Vector::operator[](int i) {
    return arr_[i];
}
```

Метод возвращает ссылку на элемент внутреннего массива. Поэтому присваивание записывает число прямо в этот элемент:

```cpp
Vector v(3);
v[0] = 42;
int& first = v[0];
first = 9;
std::cout << v[0] << '\n'; // 9
```

Если бы метод возвращал `int` по значению, вызывающий код получал бы отдельное число, а не доступ к элементу. Выражение `v[0] = 42` с таким возвращаемым типом не компилировалось бы.

Наш `operator[]` не проверяет границы. Допустимы только индексы `0 <= i && i < v.size()`. Для пустого вектора допустимых индексов нет. Выход за границы — неопределённое поведение, а не гарантированное сообщение об ошибке.

## Где стоит const в объявлении метода

Посмотрим на объявление из нашего класса:

```cpp
const int& operator[](int i) const;
```

Первый `const` относится к **результату**: через возвращённую ссылку нельзя изменить элемент. Последний `const` относится к **объекту, у которого вызвали метод**. Эти ограничения независимы. Кроме того, `const` может стоять в типе параметра и ограничивать работу с аргументом.

**`const` после скобок: доступ к самому объекту.**

```cpp
int Vector::size() const {
    return size_;
}
```

Последний `const` позволяет вызвать `size()` у константного вектора. Внутри этого метода нельзя присвоить новое значение полям нашего класса: например, `size_ = 100` или `arr_ = nullptr` не скомпилируются. Через `this` объект доступен как константный `Vector`.

```cpp
Vector editable(3);
const Vector fixed(5);
const Vector& view = editable;

std::cout << editable.size() << '\n'; // 3
std::cout << fixed.size() << '\n';    // 5
std::cout << view.size() << '\n';     // 3
```

Константный метод можно вызывать и у обычного объекта. Но метод без завершающего `const` нельзя вызвать через константный объект или константную ссылку — даже если его тело фактически ничего не меняет. Компилятор ориентируется на объявление метода.

По той же причине внутри константного метода нельзя вызвать у `this` обычный неконстантный метод. В объявлении класса и определении метода завершающий `const` должен совпадать.

**`const` у возвращаемого типа: доступ через результат.**

Для индексирования возвращаем ссылку на элемент:

```cpp
const int& Vector::operator[](int i) const {
    return arr_[i];
}
```

Первый `const` запрещает записывать число через эту ссылку. Он сам по себе не запрещает методу менять поля и не разрешает вызов у константного объекта — за это отвечает `const` после скобок.

Сравните эти два возможных объявления:

```cpp
const int& operator[](int i);       // Результат только для чтения; метод неконстантный.
const int& operator[](int i) const; // Результат только для чтения; метод константный.
```

Первая версия не подойдёт для чтения из `const Vector`, несмотря на `const` в начале строки. В нашем классе для такого чтения используется вторая.

У результата-указателя действуют те же правила, что мы разобрали выше: например, `const int*` запрещает запись через возвращённый указатель. Это тоже не заменяет `const` после скобок метода.

Для простого числа, возвращаемого **по значению**, ситуация другая:

```cpp
// Сравнение двух вариантов объявления, а не изменение интерфейса проекта.
const int size(); // const относится к возвращаемому числу; метод неконстантный.
int size() const; // Метод константный; возвращается отдельное число.
```

В первом варианте `const` у результата не защищает состояние вектора. Для возвращаемого по значению `int` такой `const` не даёт полезного ограничения вызывающему коду. Во втором варианте можем читать размер константного вектора; именно он используется в проекте.

```cpp
const Vector v(3);
int count = v.size();
count = 100; // Меняется отдельная переменная count, а не размер v.
```

**`const` у параметра: доступ к переданному аргументу.**

В следующем фрагменте показан возможный метод для записи первого элемента. В проект добавлять его не требуется:

```cpp
void setFirst(const int value) {
    if (size_ > 0) {
        arr_[0] = value;
    }
    // value = 0; // Ошибка: локальный параметр константный.
}
```

Параметр передан по значению. `const` запрещает менять локальную копию `value` внутри метода, но метод может менять вектор. У объекта, из которого получили аргумент, константность от этого не меняется. Объявления `void setFirst(int value)` и `void setFirst(const int value)` не задают разные перегрузки: для параметра по значению это одна сигнатура.

Если параметр имеет тип `const Vector&`, ограничение относится к доступу через ссылку на переданный вектор. Оно не делает константным объект, у которого вызван метод. Например, в объявлении `Vector& operator=(const Vector& vec)` источник доступен только для чтения, а получатель изменяется. Подробно этот оператор разберём в следующей части.

## Как два const работают при индексировании

В нашем классе есть две перегрузки:

```cpp
int& operator[](int i);
const int& operator[](int i) const;
```

Для обычного вектора выбирается первая версия: она позволяет изменять элемент. Для константного вектора или константной ссылки на него доступна вторая:

```cpp
Vector v(3);
v[0] = 42;
const Vector& view = v;
std::cout << view[0] << '\n'; // 42
// view[0] = 7; // Ошибка компиляции.
```

Здесь важны обе части объявления: последний `const` разрешает вызвать метод через `view`, а первый запрещает запись через результат вызова. Различие только в возвращаемом типе не позволило бы перегрузить функцию; эти методы различаются завершающим `const`.

Есть тонкость уже знакомого разделения указателя и данных: в константном методе нельзя перенаправить поле `arr_`, но память, на которую оно указывает, автоматически константной не становится. Внутри метода технически можно записать в `arr_[0]`. Автор класса должен соблюдать обещание не менять содержимое; возвращаемый тип `const int&` защищает доступ снаружи.

**Проверьте себя:** разрешит ли объявление `const int size()` вызвать метод у `const Vector`? А объявление `int size() const`?

Первое — нет: константность результата не делает метод константным. Второе — да: `const` после скобок относится к объекту, у которого вызывается метод.

## Передать вектор в функцию

Функция, которой нужно только прочитать размер, принимает ссылку на константный объект:

```cpp
int readSize(const Vector& v) {
    return v.size();
}
```

Параметр обозначает исходный объект без создания нового вектора и не разрешает менять его через этот параметр. Привязка ссылки к переданному объекту сохраняется на всё время вызова. Такая функция принимает как обычный, так и константный `Vector`.

Если нужно изменить объект вызывающего кода, передадим обычную ссылку:

```cpp
void setFirst(Vector& v, int value) {
    if (v.size() > 0) {
        v[0] = value;
    }
}
```

У параметра `Vector v` без `&` другая семантика: при вызове с существующим вектором создаётся самостоятельная копия. Копирование класса, владеющего памятью, нужно реализовать правильно — это следующий шаг.

Обратите внимание и на `auto`:

```cpp
Vector v(1);
v[0] = 10;
auto value = v[0]; // int: отдельное число.
auto& ref = v[0];  // int&: ссылка на элемент.
value = 20;       // v[0] не меняется.
ref = 30;         // v[0] становится 30.
```

`auto` просит компилятор вывести тип из инициализатора; тип остаётся определённым во время компиляции. Чтобы сохранить ссылку в этом примере, нужно явно написать `&`.

**Перед продолжением:** изменится ли `v[0]`, если выполнить `int n = v[0]; n = 99;`? А если заменить `int` на `int&`?

В первом случае меняется копия числа, во втором — элемент вектора.
