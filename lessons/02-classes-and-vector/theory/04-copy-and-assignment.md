# Копирование и присваивание

В предыдущих частях мы научились создавать вектор, освобождать его память и обращаться к нему через ссылки и указатели. Но в программе часто требуется сохранить несколько версий одних и тех же данных и работать с ними независимо.

Представим, что вектор содержит результаты измерений. Мы хотим попробовать исправление: изменить несколько значений, проверить результат и только после этого принять новую версию. Исходные измерения должны оставаться доступными, пока мы не решили их заменить.

Ссылка здесь не даст отдельную рабочую версию. Как мы уже видели, она обозначает тот же объект: изменение через ссылку сразу изменит исходные данные. Чтобы сохранить исходное содержимое, нужен второй вектор со своими элементами.

Вот как хотим записывать эту работу после реализации копирования:

```cpp
Vector measurements(2);
measurements[0] = 10;
measurements[1] = 20;

Vector corrected = measurements; // Создаём независимую рабочую копию.
corrected[0] = 12;                // Исходные measurements ещё содержат 10 и 20.

// Допустим, мы проверили исправление и решили его принять.
measurements = corrected;         // Заменяем содержимое исходного вектора.
```

Здесь две разные потребности. Сначала нужно **создать ещё один объект с теми же значениями**, чтобы менять его независимо. Позже нужно **заменить значения в уже существующем объекте**, сохранив сам объект. Такие ситуации встречаются при подготовке рабочих копий данных, сохранении промежуточных результатов и обновлении текущего состояния программы.

Для обычного `int` мы уже привыкли к такому поведению: присвоив одному числу значение другого, можно изменять их независимо. От нашего `Vector` хотим того же — чтобы он представлял самостоятельную последовательность чисел, которую можно скопировать и затем заменить другой последовательностью.

Но внутри `Vector` есть динамическая память. Нужно решить, кто выделит массив для копии, что делать с прежним массивом при замене содержимого и кто потом освободит оба массива. Эти решения должен принимать автор класса. Пользователь вектора должен иметь возможность написать показанные строки, не копируя элементы и не освобождая память вручную при каждом использовании.

Для этого реализуем две функции: **конструктор копирования** создаёт новый объект по образцу существующего, а **оператор копирующего присваивания** заменяет содержимое уже созданного объекта. Термина «конструктор присваивания» здесь нет: присваивание не начинает жизнь объекта заново.

Копия нужна не при каждом обращении к вектору. Для чтения существующих данных уже подходит `const Vector&`, а для изменения того же объекта — `Vector&`. Копирование выбираем, когда действительно требуется самостоятельное содержимое.

## Главный вопрос: объект создаётся или уже существует

Сравним два фрагмента. В первом сразу создаём `b` как копию `a`:

```cpp
Vector a(2);   // Конструктор с размером.
a[0] = 10;
Vector b = a;  // Конструктор копирования: b появляется на этой строке.
```

Во втором сначала создаём пустой `b`, а затем присваиваем ему содержимое `a`:

```cpp
Vector a(2); // Конструктор с размером.
a[0] = 10;
Vector b;    // Конструктор без аргументов: b уже создан.
b = a;       // Копирующее присваивание: меняем существующий b.
```

В обоих случаях в конце `b` содержит те же числа, что и `a`. Но во втором фрагменте для `b` выполнены две операции: создание пустого объекта и последующее присваивание. Пустой вектор — тоже существующий объект, даже если он ещё не владеет массивом.

**Сам знак `=` не определяет, какая функция вызывается.** В объявлении `Vector b = a;` он задаёт начальное значение нового объекта. В выражении `b = a;` он означает присваивание существующему объекту.

При обеих операциях хотим получить самостоятельное содержимое:

```cpp
Vector a(2);
a[0] = 10;
Vector b = a;
b[0] = 99;
std::cout << a[0] << ' ' << b[0] << '\n'; // 10 99
```

Изменение копии не должно менять исходный вектор. Разберём, как реализовать это правило, а затем проследим вызовы в параметрах функций, ссылках и возвращаемых результатах.

## Почему копии указателя недостаточно

Если не определить собственное копирование, неявно созданный конструктор копирования нашего класса скопирует его поля. Число `size_` скопируется как число, а `arr_` — как адрес. Сам массив при этом не копируется:

```text
копирование полей:                 нужное нам копирование:

a.arr_ ──┐                         a.arr_ ───► [10, 0]
         ├──► [10, 0]
b.arr_ ──┘                         b.arr_ ───► [10, 0]
```

Слева изменение через `b` затрагивает `a`. Ещё хуже, оба деструктора попытаются удалить один массив. Второе удаление — неопределённое поведение.

В C присваивание структуры с указателем тоже копирует значение указателя, а не выделенный по нему массив. В C++ появляется возможность определить, что означает копирование нашего типа. Поэтому здесь нельзя бездумно полагаться на копирование полей.

## Создать новый объект по образцу существующего

В публичной части класса объявим `Vector(const Vector& vec);`. Это **конструктор копирования**. Он получает исходный объект по ссылке для чтения:

```cpp
Vector::Vector(const Vector& vec) : arr_(nullptr), size_(vec.size_) {
    if (size_ > 0) {
        arr_ = new int[size_];
    }
    for (int i = 0; i < size_; ++i) {
        arr_[i] = vec.arr_[i];
    }
}
```

Сначала выделяем собственную память, затем записываем в неё каждый элемент. До записи новые элементы не читаем. Такое копирование содержимого в отдельный буфер называют **глубоким копированием**.

Метод класса может обращаться к закрытым полям другого объекта того же класса. Поэтому `vec.arr_` здесь допустим: `private` ограничивает доступ по классу, а не по конкретному экземпляру.

Теперь пример с изменением копии выведет `10 99`. У пустого вектора копия также пустая: массив не выделяется, цикл не выполняется.

## Заменить содержимое существующего объекта

Здесь оба объекта уже созданы:

```cpp
Vector a(2);
a[0] = 10;
Vector b(5);
b = a;
```

Конструктор для `b` второй раз не вызывается. Вместо него вызывается **оператор копирующего присваивания**. Объявление в классе: `Vector& operator=(const Vector& vec);`.

Нужно освободить прежний массив `b` и получить копию массива `a`. Но порядок действий имеет значение: сначала подготовим новый массив и только затем удалим старый.

```cpp
Vector& Vector::operator=(const Vector& vec) {
    if (this == &vec) {
        return *this;
    }

    int* newArr = nullptr;
    if (vec.size_ > 0) {
        newArr = new int[vec.size_];
    }
    for (int i = 0; i < vec.size_; ++i) {
        newArr[i] = vec.arr_[i];
    }

    delete[] arr_;
    arr_ = newArr;
    size_ = vec.size_;
    return *this;
}
```

`this == &vec` сравнивает адреса получателя и источника. Если это один объект, встретилось **самоприсваивание** `a = a`; достаточно вернуть его без изменений.

Если `new[]` не сможет выделить память, старый массив ещё существует и поля получателя не изменены. Когда новый массив готов, можно удалить прежний и обновить поля. Для нашего массива `int` копирование элементов не выбрасывает исключений. При других типах элементов управление ошибками потребовало бы отдельного разбора.

`*this` обозначает сам объект-получатель. Возвращаем ссылку на него, поэтому выражение присваивания можно использовать дальше: `a = b = c` сначала присваивает `c` объекту `b`, затем `b` объекту `a`.

После присваивания размер `b` станет 2. Объект `b` остался тем же, но его прежний массив уничтожен. Ссылки и указатели на элементы этого старого массива больше использовать нельзя.

## Узнать операцию по месту использования

**Разные формы создания копии.** Все три объявления ниже вызывают конструктор копирования:

```cpp
Vector a(2);
Vector b(a);    // Новый b создаётся из a.
Vector c = a;  // Новый c создаётся из a.
Vector d{a};   // Новый d создаётся из a.
```

В каждом случае появляется новый `Vector`. Круглые скобки, знак `=` и фигурные скобки здесь задают разные формы записи инициализации. Для нашего интерфейса все три используют конструктор `Vector(const Vector&)`.

**Передача по значению и по ссылке.** Параметр функции тоже может быть новым объектом:

```cpp
void changeCopy(Vector v) {
    v[0] = 99;
}

void changeOriginal(Vector& v) {
    v[0] = 99;
}

void compareParameters() {
    Vector a(1);
    a[0] = 10;

    changeCopy(a);     // Конструктор копирования создаёт параметр v.
    std::cout << a[0] << '\n'; // 10

    changeOriginal(a); // Привязка ссылки; нового Vector нет.
    std::cout << a[0] << '\n'; // 99
}
```

В этом примере обе функции вызываются только с непустым вектором. У `changeCopy` параметр `v` получает собственный массив; после вызова копия уничтожается. У `changeOriginal` параметр обозначает сам `a`.

Строка `v[0] = 99` присваивает значение отдельному `int`. Она не вызывает оператор присваивания `Vector`. Тип объекта слева тоже важен: меняется элемент, а не весь вектор.

Параметр `const Vector&` аналогично связывается с существующим объектом без создания копии, но запрещает менять его через этот параметр.

**Создание параметра и присваивание внутри одной функции.** Здесь происходят обе операции:

```cpp
void replaceCopy(Vector target, const Vector& source) {
    target = source; // Копирующее присваивание существующему параметру.
}

void compareCallAndBody() {
    Vector a(1);
    a[0] = 10;
    Vector b(2);
    b[0] = 20;

    replaceCopy(a, b); // Конструктор копирования создаёт target из a.
    std::cout << a.size() << ' ' << a[0] << '\n'; // 1 10
}
```

Перед выполнением тела `replaceCopy` создаётся параметр `target` — это копия `a`. Затем строка `target = source` меняет уже созданный `target`, используя содержимое `b`. Исходный `a` остаётся прежним. Объявление параметра и выражение внутри функции — разные места, их нужно разбирать отдельно.

**Ссылки и указатели сами по себе не создают копию вектора.**

```cpp
Vector a(1);
Vector b(2);
Vector& alias = a; // Привязка ссылки, конструктора Vector нет.
Vector* p = &a;    // Создание указателя, конструктора Vector нет.

alias = b; // Копирующее присваивание объекту a через ссылку.
*p = b;    // Копирующее присваивание объекту a через указатель.
p = &b;    // Меняется только адрес в p; присваивания Vector нет.
```

На строке `alias = b` ссылка не перепривязывается: она по-прежнему обозначает `a`. Поэтому операция применяется к существующему `a`. На строке `p = &b` слева находится сам указатель; поля и массивы обоих векторов не меняются.

**Копирование из константного источника.**

```cpp
const Vector source(2);
Vector copy = source;   // Конструктор копирования.
Vector assigned;
assigned = source;      // Копирующее присваивание.
const Vector frozen = source; // Конструктор копирования.
// frozen = assigned;   // Ошибка: существующий frozen изменять нельзя.
```

Обе специальные функции принимают источник как `const Vector&`: для чтения содержимого его не нужно изменять. Константный объект можно создать копированием, но затем присвоить ему другое содержимое нельзя.

**Возврат копии из функции.** Для этого примера функция получает ссылку на уже существующий объект:

```cpp
Vector makeCopy(const Vector& source) {
    return source; // Конструктор копирования создаёт объект-результат.
}

void compareReturnAndAssignment() {
    Vector a(2);
    a[0] = 10;

    Vector b = makeCopy(a); // b инициализируется результатом функции.
    b = makeCopy(a);        // Результат присваивается существующему b.
}
```

На `return source` создаётся самостоятельная копия исходного вектора. При `Vector b = makeCopy(a)` результат становится новым `b`: оператор присваивания не вызывается. В используемом на курсе C++20 отдельная промежуточная копия результата для такого объявления не требуется.

На следующей строке `b = makeCopy(a)` функция сначала создаёт новый результат копированием `a`, а затем вызывается оператор копирующего присваивания для уже существующего `b`. После этой строки временный результат уничтожается.

Этот пример специально возвращает копию объекта по константной ссылке. Для `return` с локальной переменной действуют дополнительные правила устранения копий; их не нужно разбирать, чтобы отличить инициализацию `b` от присваивания ему. К результатам операций вернёмся в следующей части.

## Три функции работают вместе

У нашего класса три связанные обязанности:

1. Деструктор освобождает собственный массив.
2. Конструктор копирования создаёт новый объект с отдельным массивом.
3. Копирующее присваивание заменяет содержимое уже существующего объекта.

Если класс сам владеет ресурсом и ему требуется одна из этих функций, обычно следует проверить необходимость двух остальных. Это **правило трёх**. Оно не требует писать эти функции вручную для каждого класса: здесь они нужны именно из-за владения памятью через сырой указатель.

**Перед продолжением:** сначала самостоятельно назовите операцию в каждой пронумерованной строке.

```cpp
Vector a(2);
Vector b = a;          // 1
Vector c;              // 2
c = a;                 // 3
Vector& alias = c;     // 4
alias = b;             // 5
Vector* p = &a;        // 6
*p = c;                // 7
b[0] = a[0];           // 8
Vector d(b);           // 9
b = b;                 // 10
```

<summary>Ответы</summary>

1. Конструктор копирования создаёт `b` из `a`.
2. Конструктор без аргументов создаёт пустой `c`.
3. Оператор копирующего присваивания меняет `c`.
4. Ссылка связывается с `c`; нового вектора нет.
5. Оператор копирующего присваивания меняет `c` через `alias`.
6. Создаётся указатель на `a`; нового вектора нет.
7. Оператор копирующего присваивания меняет `a` через `p`.
8. Присваивается значение элемента `int`; оператор присваивания `Vector` не вызывается.
9. Конструктор копирования создаёт `d` из `b`.
10. Вызывается оператор копирующего присваивания; наша проверка самоприсваивания сразу возвращает объект без изменений.
