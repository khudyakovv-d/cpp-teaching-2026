# Занятие 6. Наследование и полиморфизм

Программа работает с разными фигурами: у круга есть радиус, у прямоугольника — ширина и высота. Для каждой фигуры нужно вычислить площадь. Хотелось бы написать общий код, который запрашивает площадь и не проверяет каждый раз, какая именно перед ним фигура.

Наследование позволяет описать общий интерфейс, а виртуальные функции — выбрать реализацию для конкретного объекта. Разберём, когда такая связь уместна, как устроен объект производного класса и как безопасно работать с ним через базовый тип.

Материалы идут в таком порядке:

1. [От отношений между объектами к наследованию](theory/01-relations-and-inheritance.md) — наследование, композиция, невладеющие связи, синтаксис, доступ, создание и копирование базовой части.
2. [Виртуальные функции и таблица вызовов](theory/02-lifetime-and-virtual-functions.md) — `override`, несколько слотов `vtable`, выбор функции через базовый указатель и ссылку, срезка и вызовы на разных стадиях жизни объекта.
3. [Виртуальный деструктор и использование интерфейса](theory/03-interfaces-and-ownership.md) — полная цепочка уничтожения, абстрактная фигура и `unique_ptr`, собственные исключения и механизм вызова методов фикстуры.
4. [Демонстрационный проект](practice/README.md) — готовые примеры и команды запуска.

После занятия студент сможет выбрать между наследованием и полем класса, объяснить порядок создания и уничтожения объекта, проследить выбор реализации через `vptr` и `vtable`, объяснить необходимость виртуального деструктора при удалении через базовый указатель и организовать безопасное владение через `std::unique_ptr<Shape>`.

Нужны [классы, ссылки и копирование](../02-classes-and-vector/README.md), [раскрутка стека](../03-exceptions/README.md) и [умные указатели](../04-move-and-smart-pointers/README.md). В занятии 5 уже встречалась запись `class VectorTest : public ::testing::Test`; теперь разберём её смысл. Примеры рассчитаны на C++20. Собственные шаблоны и приведения типов здесь не нужны.

Основной пример развивается последовательно: `Shape` хранит идентификатор, `Circle` добавляет радиус; затем методы становятся виртуальными и появляется обязательная операция площади. Данные и конструкторы сохраняются. Примеры `Base`/`Derived` отдельно показывают время жизни, а модель `Test` объясняет работу библиотеки. Блоки кода не нужно механически объединять в один файл. Нужные заголовки указаны рядом с фрагментами. Полный запускаемый проект находится в `practice`. В каждой части есть вопросы с ответами для самопроверки.

Для типов и связей используем UML-диаграммы классов, для порядка вызовов — UML-диаграмму последовательности. Их обозначения вводятся рядом с первым примером. Схемы памяти и таблиц виртуальных функций отдельно иллюстрируют типичную реализацию C++.
