# Наследник и базовый интерфейс

В занятии 6 круг передавался в функцию, принимающую `Shape&`. Функции не требовался отдельный вариант для круга: она пользовалась операциями фигуры. Такое обращение разрешено благодаря публичному наследованию `Circle : public Shape`.

У слова `public` здесь есть конкретное последствие: внешний код может обратиться к базовой части круга. Выясним, когда это удобно и что меняют два других варианта — `private` и `protected`.

В записи `class Circle : public Shape` слово `public` после двоеточия задаёт **доступ к базе**. Метка `public:` внутри тела класса задаёт **доступ к объявленным там членам**. Это разные настройки: класс может скрыть свою базу и при этом предоставить собственные публичные методы.

## Когда наследник должен быть доступен как база

Для сравнения трёх вариантов возьмём небольшой счётчик. Это отдельный пример: его операции позволят наблюдать доступ без повторного объявления всей иерархии фигур.

```cpp
class Counter {
public:
    int value() const { return value_; }

protected:
    void increment() { ++value_; }

private:
    int value_ = 0;
};
```

Внешний код может читать значение через `value()`. Увеличивать его через `increment()` могут методы самого класса и подходящих наследников. Поле `value_` закрыто: наследник напрямую к нему не обращается, а использует операции базы. Это уже знакомые уровни доступа **к членам класса**.

Теперь счётчик посетителей: новое событие увеличивает число посещений, а прочитать результат можно обычным интерфейсом счётчика.

```cpp
class VisitorCounter : public Counter {
public:
    void recordVisit() { increment(); }
};

VisitorCounter visitors;
visitors.recordVisit();
int count = visitors.value(); // 1
const Counter& counter = visitors;
int sameCount = counter.value(); // 1
// visitors.increment(); // Ошибка: защищённый метод не стал публичным.
```

`public Counter` разрешает внешнему коду получить ссылку или указатель на базовую часть. Здесь не создаётся ещё один счётчик: `counter` обозначает часть того же объекта `visitors`. Публичные члены базы доступны как публичные, защищённые — как защищённые.

Это **публичное наследование**. По смыслу `VisitorCounter` подходит туда, где ожидается `Counter`. Аналогично круг подходит к интерфейсу фигуры. Компилятор разрешает подстановку, а программист отвечает за соблюдение договора базового интерфейса.

## Когда база нужна только реализации класса

Аппарат выдачи талонов тоже использует счётчик: при каждом запросе он увеличивает номер и возвращает его. Но внешний интерфейс аппарата — получение следующего талона. Подставлять аппарат в код, ожидающий обычный счётчик, не требуется.

```cpp
class TicketMachine : private Counter {
public:
    int nextTicket() {
        increment();
        const Counter& counter = *this;
        return counter.value();
    }
};

TicketMachine machine;
int ticket = machine.nextTicket(); // 1
// machine.value();              // Ошибка: унаследованный метод закрыт.
// Counter& counter = machine;   // Ошибка: закрытая база во внешнем коде.
```

Это **закрытое наследование**. Публичные и защищённые члены базы доступны как закрытые члены `TicketMachine`. Методы аппарата могут вызывать `value()`, `increment()` и получать базовую ссылку на себя. Обычный внешний код через эту связь не может неявно преобразовать аппарат в счётчик.

Если от `TicketMachine` унаследовать ещё один класс, его методы смогут вызвать публичный `nextTicket()`, но прямого доступа к `Counter::value()` и `Counter::increment()` через эту цепочку не получат: закрытая граница находится в `TicketMachine`.

Часто использование готовой реализации удобнее выразить полем класса. В нашем примере можно хранить внутри аппарата число и увеличивать его в `nextTicket()`; наследование для этого не обязательно. Закрытое наследование бывает полезно, когда нужны именно возможности наследника — например, доступ к защищённой операции. Это инструмент реализации, который следует сравнивать с композицией.

## Если доступ нужен дальнейшим наследникам

Есть промежуточная задача: внешний код должен видеть только интерфейс измерителя, а его наследникам нужен доступ к счётчику.

```cpp
class Meter : protected Counter {
public:
    int reading() const { return value(); }
};

class EventMeter : public Meter {
public:
    void recordEvent() { increment(); }

    int readBase() const {
        const Counter& counter = *this;
        return counter.value();
    }
};

EventMeter meter;
meter.recordEvent();
int count = meter.reading(); // 1
int sameCount = meter.readBase(); // 1
// meter.value();            // Ошибка во внешнем коде.
// Counter& counter = meter; // Ошибка во внешнем коде.
```

При **защищённом наследовании** публичные и защищённые члены базы доступны как защищённые. Методы дальнейшего наследника `EventMeter` могут вызывать их и преобразовывать свой объект к `Counter`. Внешнему коду эта базовая связь не открыта. Если следующий шаг наследования станет закрытым, он поставит новую границу доступа.

Во всех трёх вариантах базовая часть присутствует в объекте и создаётся обычным образом. Вид наследования не открывает закрытое поле `Counter::value_`. Правила `protected` для обращения к чужим объектам из занятия 6 продолжают действовать.

## Что происходит по умолчанию

Если доступ к базе не указан, значение по умолчанию определяется объявлением наследника:

```cpp
class HiddenCounter : Counter {}; // private Counter
struct OpenCounter : Counter {};  // public Counter
```

Неважно, объявлена ли сама база через `class` или `struct`. Эти значения по умолчанию относятся к доступу и не меняют устройство уже объявленного базового класса.

**Проверьте себя:** почему внешний код может передать `VisitorCounter` в функцию с параметром `const Counter&`, а `TicketMachine` — нет? Кто получает доступ при `protected Counter`? Станет ли поле `value_` доступно наследнику при `public Counter`?

**Ответ:** публичное наследование открывает подстановку через базовый интерфейс обычному внешнему коду, а закрытое её не открывает; внутри непосредственного наследника она доступна. Защищённое наследование сохраняет доступ также для подходящих дальнейших наследников. Закрытое поле самой базы напрямую не открывается ни в одном варианте.

Правила: [Accessibility of base classes and base class members](https://eel.is/c++draft/class.access.base) в рабочем проекте стандарта C++.
